# Архитектура: Постквантовая криптография (PQ) и защита от DPI в ADA Messenger

## 1. Введение и цели

Данный документ описывает реализацию постквантовой криптографии (Post-Quantum Cryptography, PQC) и маскировки сетевого трафика (DPI Morpher) в ADA Messenger.

### Ключевые требования
1. **Защита от Harvest-Now-Decrypt-Later (HNDL)**: противники, перехватывающие и сохраняющие зашифрованный трафик сегодня, не смогут расшифровать его в будущем с появлением квантовых компьютеров (алгоритм Шора).
2. **NIST FIPS 203 ML-KEM-768**: использование стандартизированного решёточного механизма инкапсуляции ключей (Category 3 / эквивалент AES-192).
3. **Бесшовная деривация из Pattern Auth**: постквантовые ключи детерминированно выводятся из мастер-сида графического пароля (Argon2id), не требуя от пользователя дополнительных действий.
4. **Маскировка DPI (DpiMorpher) и Cloudflare Bridge**: двухуровневая защита от цензуры: полиморфный обфускатор `DpiMorpher` для P2P-трафика (формат записей TLS 1.3, корзины длин и потоковое HKDF-маскирование) плюс резервный шлюз `Cloudflare Worker Bridge` с полноценным доверенным сертификатом TLS 1.3 под жесткую цензуру.
5. **Сохранение чистоты транспорта**: строго `iroh-only` QUIC-транспорт без использования `libp2p`.

## 2. Постквантовая криптография (`ada-core::crypto::pq`)

### 2.1 Выбор алгоритма и параметры
- **Алгоритм**: NIST FIPS 203 ML-KEM-768 (крейт `fips203`).
- **Размеры ключей и структур**:
  - Публичный ключ инкапсуляции ($EK$): **1184 байта**
  - Секретный ключ декапсуляции ($DK$): **2400 байт** (защищён автоматическим затиранием `ZeroizeOnDrop`)
  - Шифротекст ($CT$): **1088 байт**
  - Общий секрет ($SS$): **32 байта**

### 2.2 Детерминированная деривация из графического ключа
В [ada-core/src/identity.rs](../../ada-core/src/identity.rs):
```text
Pattern Auth (16 ячеек x 5 цветов, 85.9 бит энтропии)
  ↓ Argon2id (64 MiB, t=3, p=1)
master_seed (32 байта)
  ├─ HKDF("ada/signing-key/v1")         → Ed25519 Identity Key (32 B)
  ├─ HKDF("ada/dh-key/v2")              → X25519 Identity Key (32 B)
  ├─ HKDF("ada/pq-spk-derive/epoch/N")  → 32-байтный seed → ML-KEM-768 Keypair
  └─ HKDF("ada/db-key/v1")              → SQLCipher Storage Key (32 B)
```

### 2.3 PQXDH (Post-Quantum Extended Triple Diffie-Hellman)
В [ada-core/src/crypto/x3dh.rs](../../ada-core/src/crypto/x3dh.rs):
- `PreKeyBundle` расширен полями:
  - `pq_spk_public: Option<Vec<u8>>` (ML-KEM-768 EK)
  - `pq_spk_signature: Option<Vec<u8>>` (Ed25519 подпись над публичным ключом KEM)
- **Гибридный расчет общего секрета**:
  $$\text{IKM} = [0\text{xFF}; 32] \parallel \text{DH}_1 \parallel \text{DH}_2 \parallel \text{DH}_3 \parallel [\text{DH}_4] \parallel \text{PQ\_SharedSecret}$$
  где `PQ_SharedSecret` — результат инкапсуляции/декапсуляции ML-KEM-768.
- Полученный 32-байтный результат инициализирует Double Ratchet.

### 2.4 Гибридный Double Ratchet (SPQR)
В [ada-core/src/crypto/ratchet.rs](../../ada-core/src/crypto/ratchet.rs):
- При каждом асимметричном шаге (смене направления диалога):
  - Генерируется новая пара ML-KEM-768.
  - Следующее поколение корневого ключа обновляется с подмешиванием как классического X25519 DH, так и декапсулированного секрета ML-KEM:
    $$\text{RootKey}_{i+1}, \text{ChainKey}_{i+1} = \text{HKDF}(\text{RootKey}_i, \text{DH\_Out} \parallel \text{PQ\_Out})$$
- При последовательных сообщениях одного отправителя KEM-ключи повторно не генерируются (работают симметричные KDF-шаги), что предотвращает оверхед по трафику.

## 3. Маскировка трафика и обход цензуры (`DpiMorpher` и Cloudflare Bridge)

В системе реализована **двухуровневая (эшелонированная) защита от сетевой цензуры**:

```text
┌────────────────────────────────────────────────────────────────────────┐
│             1-й ЭШЕЛОН: DpiMorpher (ada-core/src/network/dpi.rs)       │
│  • Назначение: P2P-трафик и Iroh DERP-реле без центральных серверов   │
│  • Механизм: формат записей TLS 1.3 Record + HKDF-SHA256 маскирование  │
│  • Защита: от пассивного DPI, сигнатурного анализа и корзин длин      │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
       При агрессивных блокировках (Active Probing / ковровый бан UDP)
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│     2-й ЭШЕЛОН: Cloudflare Worker Bridge (cf-workers/serverless-bridge)│
│  • Назначение: обход глубокой фильтрации государственного уровня (ТСПУ)│
│  • Механизм: WebSocket over TLS (wss://) / HTTP POST на порт 443      │
│  • Сертификат: настоящий X.509 от Google Trust Services / DigiCert     │
│  • Защита: полная неотличимость от легального веб-серфинга             │
└────────────────────────────────────────────────────────────────────────┘
```

### 3.1 1-й эшелон: Полиморфный `DpiMorpher` (P2P и реле)

В [ada-core/src/network/dpi.rs](../../ada-core/src/network/dpi.rs):

1. **Мимикрия под TLS 1.3 Record Layer:**
   Каждый кадр оборачивается в формат записи TLS 1.3 Application Data:
   - Заголовок записи: `0x17 0x03 0x03` (23 = Application Data, 3, 3 = TLS 1.2 legacy version per RFC 8446).
   - 2 байта длины записи (Big-Endian).
   - 16 байт криптографической соли (`OsRng`).
   - Замаскированное тело полезной нагрузки и паддинг.

2. **Потоковое маскирование (HKDF-SHA256 Stream Mask):**
   Чтобы в потоке не было постоянных открытых заголовков ADA или повторяющихся паттернов, длина и полезная нагрузка XOR-маскируются псевдослучайной гаммой:
   $$\text{Mask} = \text{HKDF-Expand}(\text{PRK} = \text{HKDF-Extract}(\text{Salt}, \text{Key}), \text{"ADA-DPI-TLS-STREAM-v1"}, \text{Length})$$
   Каждый пакет получает новую соль, благодаря чему даже одинаковые сообщения выглядят как совершенно разные потоки криптографического шума с максимальной энтропией ($\approx 7.99$ бит/байт).

3. **Дискретное квантование размеров (Bucket Padding):**
   Для нейтрализации статистического анализа длин пакетов (Traffic Fingerprinting) размер любого кадра выравнивается по фиксированным корзинам:
   $$\text{BucketSizes} = \{512, 1024, 2048, 3072, 4096, \dots\}$$
   Свободный остаток заполняется криптографическим шумом (`OsRng`).

4. **Границы P2P-обфускации:**
   * `DpiMorpher` не требует серверов и работает на уровне отдельных пакетов.
   * Он надежно нейтрализует пассивные анализаторы, проверку сигнатур и классификацию по длинам пакетов.
   * **Но это не полноценный веб-сервер:** у смартфона в сотовой сети нет собственного домена и закрытого ключа от сертификата X.509. Если цензор выполняет активное зондирование (шлет проверочный запрос на сокет), он обнаружит отсутствие полноценного TLS-хэндшейка.

### 3.2 2-й эшелон: Cloudflare Worker Bridge (Полноценный TLS 1.3)

В [cf-workers/serverless-bridge-worker/index.js](../../cf-workers/serverless-bridge-worker/index.js):

* Если интернет-провайдер или национальный фаервол (ТСПУ) начинает блокировать любой неизвестный UDP/QUIC-трафик, мессенджер задействует **Cloudflare Serverless Bridge**.
* **Настоящие доверенные сертификаты:** Соединение устанавливается с пограничным узлом Cloudflare CDN по протоколу **WebSocket over TLS (`wss://`)** через стандартный порт **443**.
* Сертификат выдается аккредитованными мировыми центрами сертификации (Google Trust Services / DigiCert) и принадлежит инфраструктуре Cloudflare.
* Со стороны ТСПУ и провайдера это соединение является **100% валидным веб-трафиком HTTPS**. Заблокировать его изолированно, без блокировки самого сервиса Cloudflare, невозможно.
* Внутри этого легального TLS-туннеля передаются сквозным образом зашифрованные пакеты ADA (ML-KEM-768 + Double Ratchet).

### 3.3 Сводная таблица устойчивости к методам цензуры

| Метод цензуры / DPI | Что видит цензор в DpiMorpher? | Как реагирует ADA? |
| :--- | :--- | :--- |
| **Сигнатурный анализ пакетов** | Заголовок TLS 1.3 (`0x17 0x03 0x03`), внутри белый шум (HKDF) | **Обходится 1-м эшелоном** (нет сигнатур ADA) |
| **Анализ длин пакетов (ML Fingerprint)** | Строго дискретные размеры (512, 1024, 2048 B...) | **Обходится 1-м эшелоном** (Bucket Padding) |
| **Энтропийный анализ** | Равномерная энтропия $\approx 7.99$ бит/байт | **Обходится 1-м эшелоном** (CSPRNG шум) |
| **Активное зондирование сокета (Active Probing)** | Сокет P2P не отдает веб-страницу и сертификат X.509 | **Переключение на 2-й эшелон** (Cloudflare Worker TLS) |
| **Ковровая блокировка UDP / QUIC** | Пакеты UDP отбрасываются оператором | **Переключение на 2-й эшелон** (TCP/WebSocket порт 443) |
| **Полное отключение интернета (Шатдаун)** | Отсутствие внешних маршрутов | **Переключение на 3-й эшелон** (Off-Grid Radio Mesh) |

## 4. Графическая аутентификация: 5 цветов и палитра

В [ada-core/src/pattern_auth.rs](../../ada-core/src/pattern_auth.rs), [PatternBoardView.kt (Android)](../../android-app/app/src/main/java/com/ada/messenger/ui/components/PatternBoardView.kt), [PatternBoardView.kt (Desktop)](../../android-app/desktopApp/src/commonMain/kotlin/com/ada/messenger/desktop/ui/components/PatternBoardView.kt):

- Число цветов увеличено с 3 до **5** (`PATTERN_COLORS = 5`).
- **Сравнение энтропии**:
  - 3 цвета: $C(64, 16) \times 3^{16} \approx 2.10 \times 10^{22} \approx \mathbf{74.2\text{ бита}}$
  - 5 цветов: $C(64, 16) \times 5^{16} \approx 7.45 \times 10^{25} \approx \mathbf{85.9\text{ бита}}$
  - Рост сложности полного перебора: в **3 545 раз** ($+11.8$ бит сырой энтропии).
- **UX палитры (`PatternColorPalette`)**:
  - Под сеткой 8×8 отображается палитра из 5 цветов.
  - **1 тап**: установка выбранного цвета, повторный тап того же цвета — мгновенное стирание, тап другим цветом — мгновенная перекраска.
  - Устранена проблема 5-кратного циклического кликанья для удаления ячейки.
